Pour réserver de la mémoire partagée dans PostgreSQL, vous pouvez utiliser les paramètres shared_buffers et huge_pages. Le paramètre 'shared_buffers' initialise la quantité de mémoire que le serveur de bases de données utilise comme mémoire partagée. La valeur par défaut est généralement 128 Mo, mais elle peut être automatiquement abaissée si la configuration du noyau ne la supporte pas. Ce paramètre doit être au minimum de 128 Ko +  cuisine_connections. Des valeurs significativement plus importantes que ce minimum sont généralement nécessaires pour de bonnes performances. Si vous disposez d'un serveur dédié à la base de données, avec 1 Go de mémoire ou plus, une valeur de départ raisonnable pour ce paramètre est de 25% de la mémoire de votre système. Des valeurs importantes pour le paramètre shared_buffers nécessitent généralement une augmentation proportionnelle du max_wal_size, pour étendre dans le temps les écritures de grandes quantités de données, nouvelles ou modifiées. 

Pour réserver la mémoire partagée sur Linux et Windows, vous pouvez utiliser le paramètre 'huge_pages'. Avec huge_pages à try, le serveur tentera d'obtenir des huge pages mais se rabattra sur le défaut en cas d'échec. Avec on, cet échec empêchera le serveur de démarrer. Avec off, il n'y aura pas de demande de huge pages. L'état réel des huge pages est indiqué par la variable 'huge_pages_status'. Sous Windows, les huge pages sont connues sous le nom de large pages et vous pouvez utiliser l'Éditeur de stratégie de groupe locale (gpedit.msc) pour assigner le droit « Verrouiller les pages en mémoire » à l'utilisateur Windows qui fait tourner PostgreSQL. 

Note : Ce paramètre n'affecte que la partie principale de la mémoire partagée. Des systèmes d'exploitation comme Linux, FreeBSD et Illumos peuvent aussi utiliser les huge pages automatiquement pour les allocations mémoire normales sans demande explicite de PostgreSQL.

Pour réserver des huge pages sur Windows, vous pouvez assigner le droit « Verrouiller les pages en mémoire » à l'utilisateur Windows qui fait tourner PostgreSQL. Pour démarrer le serveur en ligne de commande en tant que processus autonome, et pas en tant que service Windows, l'invite de commande doit être exécutée en tant qu'administrateur, ou bien le contrôle de compte d'utilisateur (UAC) doit être désactivé.

Question : Comment créer un slot de réplication ?
Réponse : 
Pour créer un nouveau slot de réplication avec l'interface de la réplication en flux, vous pouvez utiliser la commande 'CREATE_REPLICATION_SLOT'. Cette commande est disponible à partir d'une connexion de réplication et elle crée un nouvel instantané (snapshot) qui montre exactement l'état de la base de données après lequel tous les changements seront inclus dans le flux de changement. Cela peut être utilisé pour créer un nouveau réplica en utilisant SET TRANSACTION SNAPSHOT pour lire l'état de la base au moment où le slot a été créé. 

Question : Comment gérer les conflits avec les requêtes sur un serveur secondaire ?
Réponse : 
Les nœuds primaire et secondaire sont faiblement couplés à bien des égards, ce qui peut entraîner des interactions négatives ou de conflits entre eux. Les utilisateurs peuvent déterminer si le Hot Standby est actuellement actif pour leur session en exécutant SHOW in_hot_standby. Si vous disposez d'un serveur secondaire en lecture seule, la création d'un instantané n'est pas toujours possible et les applications qui ne nécessitent pas d'instantané exporté peuvent les supprimer avec l'option NOEXPORT_SNAPSHOT. Pour reprendre la réplication logique après un failover à partir des slots logiques synchronisés, le paramètre conninfo de l'abonné doit être modifié pour pointer vers le nouveau serveur primaire. Il est recommandé que les souscriptions soient tout d'abord désactivées avant la promotion du secondaire, puis réactivées après avoir modifié la chaîne de connexion.

Question : Comment enregistrer une procédure de rappel pour les événements avec libpq ?
Réponse : 
Pour enregistrer une procédure de rappel pour les événements avec libpq, vous pouvez utiliser la commande 'PQregisterEventProc'. Cette commande permet d'enregistrer une procédure de rappel pour les événements. La signature d'une telle fonction doit être : int eventproc(PGEventId evtId, void *evtInfo, void *passThrough). Le paramètre 'eventId' indique l'événement PGEVT qui est survenu et le pointeur 'evtInfo' doit être converti vers le type de structure approprié pour obtenir plus d'informations sur l'événement. La fonction doit renvoyer une valeur différente de zéro en cas de succès et zéro en cas d'échec.
